# Проект Arbix Quantum

**Arbix Quantum** — це високотехнологічний асинхронний P2P-сканер та автоматизований помічник для криптовалютного арбітражу. Система розроблена для пошуку прибуткових спредів (як крос-біржових, так і внутрішньобіржових) між провідними P2P-майданчиками з глибокою інтеграцією штучного інтелекту для аналізу ризиків, автоматизованим керуванням банківськими лімітами та гнучкою системою виконання ордерів.

---

## 🛠 Технологічний стек (Tech Stack)

*   **Мова програмування:** Python 3.x (повністю асинхронна архітектура).
*   **Мережа та Concurrency:** `asyncio` для паралельного виконання завдань, `aiohttp` для неблокуючих HTTP-запитів до API бірж.
*   **База даних:** `SQLite` в режимі **WAL (Write-Ahead Logging)** через бібліотеку `aiosqlite` для забезпечення високої швидкості запису й захисту від блокувань при паралельних транзакціях.
*   **Інтерфейс бота:** `Aiogram` (Telegram-бот з розгалуженим інтерактивним меню, inline-клавіатурами та системою сповіщень).
*   **Аналітика та ШІ:** Інтеграція з великими мовними моделями (LLM: **OpenAI, Gemini, Groq**) для оцінки ризиків та верифікації контрагентів.
*   **API-сервер:** `FastAPI` (включаючи експорт метрик для Prometheus та обробку вебхуків).
*   **Developer GUI:** `PyQt6` (допоміжні інструменти розробника).

## 📱 Простий користувацький функціонал (Basic & User-Facing Features)

Це повсякденний функціонал, з яким користувач або адмін безпосередньо взаємодіє через інтерфейс Telegram-бота:

### 1. Зручне текстове керування (Команди бота)
*   `/start` — візуальний запуск бота, відкриття персонального кабінету та інтерактивного дашборду.
*   `/status` — миттєвий перегляд стану сканера (чи запущено парсинг, швидкість останнього циклу в мс, кількість ботів у стаканах, черги на ШІ та відгуки, стан запобіжників).
*   `/connect` та `/disconnect` — ручне додавання або видалення персональних API-ключів для Bybit, Binance, OKX, MEXC.
*   `/keys` — перегляд списку поточних підключених ключів бірж.
*   `/balance` — перевірка балансів на підключених спотових/фіатних рахунках бірж в реальному часі.
*   `/settings` — ручне налаштування параметрів (робочий капітал, мінімальний спред %, вибір дозволених банків тощо).
*   `/cards` — швидкий вхід у меню управління банківським пластиком.
*   `/report` — генерація звітів про рух фіатних коштів за картками.
*   `/ban` — швидке ручне додавання шахрайського мерчанта до чорного списку.
*   `/help` — список доступних команд.

### 2. Меню управління банківськими картками (`/cards`)
Користувачеві доступний повний інтерфейс для контролю свого пластику або карток дропів:
*   **Покроковий майстер додавання карти (FSM):** вибір банку зі списку ➔ введення 16-значного номера карти (з перевіркою коректності) ➔ введення поточного балансу ➔ встановлення мітки (наприклад, "Дроп Іван") ➔ вибір типу (Власна/Дроп).
*   **Швидке оновлення балансу:** можливість вручну скоригувати поточний баланс картки у системі за кілька кліків або автоматично оновити його через API Монобанку.
*   **Редагування та видалення:** швидка зміна мітки карти (Label), додавання текстових нотаток (Note), зміна категорії власника чи повне видалення карти з бази.
*   **Функція заморозки (Freeze/Active toggle):** можливість тимчасово перевести карту в статус `frozen_funds`, щоб сканер припинив підбирати її для нових угод, не видаляючи її з системи.
*   **Діагностика здоров'я карт (`card:diagnostics`):** автоматичне сканування доданих карт на наявність помилок: нульові баланси, активні кулдауни, непідключені вебхуки Монобанку або карти, які використали понад 80% ліміту.

### 3. Ручне ведення фінансової звітності (`/report`)
*   Можливість згенерувати фінансовий звіт за **24 години, 7 днів або 30 днів**.
*   Звіт групує транзакції та показує: загальний робочий оборот (IN/OUT), особисті витрати, кількість транзакцій та залишки банківських лімітів для кожної картки окремо з кольоровими позначками статусів (активна 🟢, заморожена ❄️, заблокована 🔴).

### 4. Персональні налаштування профілю (Personal Filtering)
Кожен користувач через Telegram-клавіатуру може встановити індивідуальні ліміти:
*   **Working Capital (Робочий капітал):** сума, яку користувач готовий пустити в оборот (система автоматично масштабує спреди під цей капітал). Також підтримується режим **Auto Capital** (баланс вираховується автоматично за сумою доступних лімітів та грошей на картках).
*   **Min Spread (Мінімальний спред %):** спреди з нижчим відсотком прибутку просто не надсилатимуться користувачу.
*   **Min Amount (Мінімальна сума):** ігнорування занадто дрібних ордерів (наприклад, до 500 грн).
*   **Гнучке налаштування банків:** вибір конкретних банків для покупки (BUY) та продажу (SELL) окремо, або вибір загального списку банків для роботи.

### 5. Інтеграція з Monobank для новачків
*   Підключення картки Монобанку здійснюється простим відправленням зашифрованого `X-Token` (токен автоматично ховається з чату після введення для безпеки).
*   Система самостійно зіставляє карту в Telegram з рахунком у банку за останніми 4 цифрами та підтягує реальний баланс.
*   Автоматично реєструються вебхуки на стороні Монобанку (якщо налаштований `PUBLIC_URL`), або ж бот запускає фоновий процес періодичного оновлення балансу (Fallback Sync) кожні 90 секунд.

## 🎯 Ключовий кодовий функціонал (Core Features)

### 1. Багатобіржове сканування (Multi-Exchange Scanning)
*   Одночасне паралельне сканування P2P-стаканів на біржах: **Binance, Bybit, OKX, MEXC та Telegram Wallet** (через спеціалізований Userbot).
*   Використання паттерну **Circuit Breaker** (запобіжник) для кожної біржі: якщо API тимчасово не відповідає, сканер ізолює запити до неї, запобігаючи таймаутам всього циклу.
*   **Spread Stability Filter (Фільтр стабільності):** спред надсилається користувачеві лише тоді, коли він протримався в стакані кілька сканувань поспіль (захист від фантомних ордерів та маніпуляцій).

### 2. RiskEngine — Багаторівневий аналіз ризиків (Унікальна фіча)
Це серце проекту, призначене для захисту від шахрайства (трикутні сками, «брудні» гроші, фінансовий моніторинг):
*   **CompositeScorer:** Зводить усі ризик-сигнали в єдиний бал від `0` до `100`.
*   **Шари аналізу:**
    1.  **Regex Analyzer:** Сканування тексту умов ордера (Trade Terms) на наявність підозрілих ключових слів (вимоги фото картки, затягування часу, посилання на сторонні чати тощо).
    2.  **Behavioral Analyzer (Поведінковий аналіз):** Детекція ботів у стакані. Аналізує історію активності мерчанта за останні 15+ хвилин на предмет моментального автопоповнення ордерів (`API_REPLENISH`), статичних лімітів чи блимання оголошень (`Flicker-relist`).
    3.  **Identity Analyzer (Аналіз цифрових двійників):** Пошук «мерчантів-клонів» на різних біржах з однаковими або схожими нікнеймами та поведінковими факторами.
    4.  **Review Analyzer (Аналіз відгуків):** Збір детальної статистики відгуків. Система категоризує негативні коментарі за категоріями (`TRIANGLE`, `CHARGEBACK`, `FINCRIME`, `CASINO`) і автоматично витягує тексти скарг.
*   **Синергії сигналів:** RiskEngine шукає небезпечні комбінації сигналів (наприклад, новий акаунт + робота через бота-автопоповнювача + наявність зовнішнього лінку в описі) та автоматично підвищує рівень загрози.
*   **Ші Вердикт (LLM Integration):** При високому ризику або складних комбінаціях сигналів система робить асинхронний запит до LLM (Gemini/OpenAI/Groq), передаючи їй весь контекст. LLM видає остаточне рішення: `OK`, `SUSPICIOUS` або `BLOCK`.

### 3. Автоматизація та виконання (Trade Engine)
*   **Finite State Machine (FSM):** Повністю відстежує життєвий цикл кожної угоди (запис сесії, резервування лімітів карт, створення ордерів, очікування оплати, закриття).
*   **Підтримка 4-х стратегій:**
    *   **Taker-to-Taker (TT):** Купівля тейкером на одній біржі -> продаж тейкером на іншій.
    *   **Taker-to-Maker (TM):** Швидкий вхід по чужому оголошенню -> розпродаж через власне Maker-оголошення з динамічним репрайсингом.
    *   **Maker-to-Taker (MT):** Закупівля через Maker-оголошення -> вихід по тейкеру.
    *   **Maker-to-Maker (MM):** Робота повністю в ролі Maker на обох ногах спреду.
*   **AdRepricer (Блок автоматичного репрайсингу):** Стежить за стаканом і коригує ціну вашого Maker-оголошення на Bybit/Binance, щоб ви завжди лишалися першими, але з жорстким контролем мінімальної маржі (Price Floor), враховуючи витрати на мережеві комісії.
*   **NetworkFeeEngine:** Оптимізатор переказів між біржами. Розраховує найдешевшу спільну мережу (наприклад, TRC20, BEP20, TON) для переказу активів та автоматично віднімає комісію з очікуваного прибутку.
*   **Binance Session Hijacking:** Обхід обмежень API шляхом перехоплення кук (`cookies`) та `csrftoken` активної веб-сесії користувача для збору відгуків та виконання ордерів від імені браузера.

### 4. Запобіжні заходи та безпека (Safety Guards)
*   **Volatility Stop-Loss:** Якщо spot-ціна активу здійснює різкий рух (більше ніж на X% за Y хвилин), усі Maker-оголошення миттєво переводяться в статус *Offline* для запобігання збитків.
*   **Ідентичність транзакцій (Idempotency):** Усі ордери та транзакції створюються з унікальними Client Order ID (UUID), виключаючи ризик подвійної відправки запитів.
*   **Dry Run Mode:** Можливість безпечного запуску системи, коли робота сканера, FSM-ордерів та репрайсингу повністю симулюється на фейкових даних без надсилання реальних грошових ордерів на біржі.
*   **Automated Heartbeat:** Кожен Maker-бот регулярно записує свій стан у БД. Якщо запису немає понад 60 секунд, Telegram Notifier відправляє алерт про «завислого» бота.

## ⚡ Додаткові "приколюхи" (Advanced Mechanisms)

### 💳 Розумне сплітування ордерів (Order Splitting)
Якщо ліміти банківських карток користувача обмежені:
*   **Внутрішній спліт (Internal Split):** Якщо картка має великий добовий ліміт, але сума ордера перевищує ліміт *однієї* транзакції (`max_single_tx`), система автоматично розділить платіж на дві частини (наприклад, ліміт + залишок) в межах однієї картки.
*   **Мульти-карт спліт (Multi-Card Split):** Розподіл суми ордера між кількома активними картками користувача (до 3 карток одночасно) з автоматичним резервуванням та супроводом транзакцій.

### 🧩 Асиметричний арбітраж (Asymmetric Spreads)
*   Система вміє знаходити спреди, де об'єми купленого та проданого активів на різних ногах не збігаються (наприклад, закриття великої taker-заявки серією менших ордерів). Ці пропозиції надсилаються користувачам, у яких активована функція `asymmetric_spread`.

### 🎯 Система розумної адаптації під гаманець (Wallet-Based Alert Routing)
*   Перед надсиланням сповіщення користувачу `AlertDispatcher` перевіряє перетин підтримуваних мерчантом банків з реально доданими активними картками трейдера. Картки в алерти підставляються динамічно, підлаштовуючись під наявний «пластик» (наприклад, якщо мерчант підтримує Mono/Privat/Pumb, а у трейдера активна лише Mono, алерт буде адаптовано під Monobank).

### 📉 Капітальний Down-Scaling (Масштабування ордерів)
*   Якщо спред чудовий, але його об'єм перевищує капітал користувача, система автоматично перераховує об'єми і прибутки «вниз» до ліміту капіталу користувача (якщо дозволяють мінімальні ліміти мерчантів), замість того, щоб повністю ігнорувати спред.

### 💳 Розумний підбір та ранжування карт (Scoring)
*   Алгоритм оцінює та вибирає найкращу картку для транзакції на основі балів (враховується власник карти, статус прогріву, давність використання, окупність ліміту, кількість транзакцій за добу).

### 🏃‍♂️ Одноногова торгівля (SingleLegExecutor)
*   Користувач може вручную ініціювати виконання лише однієї ноги спреду (Buy або Sell) через кнопки прямо в Telegram-каналі. Ці ордери також контролюються LLM (наприклад, якщо вердикт `CONDITIONAL`, сума угоди автоматично зрізається навпіл для зниження ризику).

### 🖥️ PyQt6 AI Context Manager (Утиліта для розробника)
*   У корінь проекту вбудована десктопна утиліта `dump_ui.py`. Вона дозволяє розробникам швидко збирати код проекту в один файл-контекст для згодовування нейромережам (Repo-to-Prompt), підраховуючи точну кількість токенів через кодери `tiktoken` та оптимізуючи розмір під ліміти контексту GPT-4, Claude 3.5 чи Gemini 1.5 Pro.

## 📂 Структура проекту та архітектурні підходи

Код структурований за принципами чистих модульних обов'язків:
1.  `bot/`: Логіка Telegram-інтерфейсу, клавіатури, форматування спредів та генерація алертів (`alert_builder.py`, `handlers/`).
2.  `core/engine/`:
    *   `risk_engine.py` — Orchestrator аналізу ризиків.
    *   `ad_repricer.py` — Скрипт утримання топ-ціни.
    *   `route_executor.py` — Низькорівнева відправка торгових запитів.
    *   `trade_worker.py` — Логіка виконання FSM кроків стратегій.
3.  `core/analysis/`: Алгоритми поведінкового аналізу, аналізу лімітів та перевірки тексту.
4.  `core/storage/`: Клієнт бази даних, репозиторії карток, мерчантів та користувачів.
5.  `exchanges/`: Обгортки API для кожної підтримуваної біржі, що наслідуються від базового класу `base.py`.
6.  `filters/`: Швидкі фільтри для відсіювання занадто великих лімітів або аномальних цін ще до етапу повного аналізу ризику.
7.  `api/`: Модульні роутери для FastAPI сервера (віддача статистики для веб-дашборду, Prometheus метрики `/metrics`, прийом вебхуків від банків).

## 📈 Моніторинг та Інтерфейси

1.  **Telegram Bot:** Основний інструмент керування для трейдера (вмикання/вимикання сканування, керування картками, налаштування капіталу та мінімального спреду, ручне підтвердження ордерів).
2.  **FastAPI Dashboard:** Веб-панель, яка зчитує статистику циклів, обсяги оброблених ордерів, поточний стан підключених сесій та знайдені спреди.
3.  **Prometheus & Grafana:** Збір та візуалізація метрик продуктивності (час сканування, розміри черги завантаження відгуків/LLM, кількість успішних/хибних кеш-спрацювань ризик-сервера).
